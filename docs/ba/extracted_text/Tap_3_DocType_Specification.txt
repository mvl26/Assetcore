3.3 Mapping ERPNext core ↔ AssetCore
3.3.1 Bảng mapping tổng
Bảng dưới ánh xạ từng khái niệm AssetCore tới ERPNext core: Tận dụng nguyên (TN), Tận dụng + custom field (TN+CF), Custom DocType mới (CD), Hoặc Không liên quan core (KL).
3.3.2 Cách Medical Asset liên kết với Asset core
Mỗi Medical Asset có quan hệ 1-1 với Asset core của ERPNext. Asset core giữ vai trò kế toán (cost center, depreciation, gross purchase amount). Medical Asset giữ vai trò HTM (risk, criticality, location, lifecycle).
```mermaid
flowchart LR
  PR[Purchase Receipt] -->|on_submit| ASSET[Asset (core)]
  ASSET -->|hook auto-create| MA[Medical Asset (custom)]
  MA -->|link asset_doc| ASSET
  MA -->|link device_model| DM[Device Model]
  MA -->|link department| DEP[Department]
  MA -->|link location| LOC[Warehouse/Location]
  MA -->|link asset_category| AC[Asset Category]
```
Quy ước naming: Asset core có name dạng `ACC-ASS-2026-00001` (Frappe default); Medical Asset có name dạng `MA-2026-00001` để dễ phân biệt khi đọc log.
3.3.3 Custom field chèn vào DocType core
3.4 DocType Specification chi tiết
Mỗi DocType custom có spec đầy đủ. Trường có ký hiệu * = mandatory; ! = unique; → = link tới DocType khác. Các trường audit `created_by`, `creation`, `modified_by`, `modified`, `docstatus`, `idx` mặc định Frappe đã có nên không liệt kê lại.

3.6.1 Định nghĩa các trường thường dùng
3.6.2 Quy ước kiểu dữ liệu
Dates: lưu định dạng ISO 8601 (YYYY-MM-DD).
Datetimes: lưu UTC; hiển thị theo timezone Asia/Ho_Chi_Minh.
Currency: VND mặc định; hỗ trợ USD/EUR cho hợp đồng nước ngoài, có exchange snapshot.
Phone number: chuẩn E.164 (vd: +84901234567).
Boolean: dùng Frappe Check (0/1) — không dùng Yes/No string.
JSON payload: lưu plain string trong Long Text; validate bằng JSON Schema khi insert.
3.7 Identifier Strategy — Asset ID đa lớp
3.7.1 Tầng định danh
```mermaid
flowchart TB
  L1["Tầng 1 — asset_id\n(MA-YYYY-NNNNN, duy nhất nội bộ)"]
  L2["Tầng 2 — primary_qr\n(QR vật lý dán trên thiết bị)"]
  L3["Tầng 3 — serial_no\n(do nhà sản xuất cấp)"]
  L4["Tầng 4 — alternate identifiers\n(asset_tag bệnh viện, regulatory_id)"]
  L1 --> L2
  L2 --> L3
  L3 -.optional.-> L4
```
3.7.2 Asset ID convention
Naming rule trong Frappe: `MA-.YYYY.-.#####`. Số thứ tự reset mỗi năm. Asset bị retire vẫn giữ ID; không tái sử dụng.
3.7.3 QR code convention
Khi user scan QR: redirect về form Medical Asset đã đăng nhập. Nếu chưa đăng nhập: hiển thị info công khai cơ bản (tên, model, location). Salt giúp phát hiện QR bị copy mà không có dữ liệu thật trong hệ thống.
3.7.4 Asset Tag bệnh viện (alternate)
Một số bệnh viện đã có hệ asset tag riêng (ví dụ: 6 chữ số do Phòng Tài chính cấp cho mục đích khấu hao). AssetCore lưu tag này dạng `Asset Identifier` với type=`asset_tag`, không phải primary.
3.7.5 Regulatory ID
Số đăng ký lưu hành Bộ Y tế và các regulatory ID khác lưu trong `Asset Identifier` với type=`regulatory_id`, có liên kết đến Document Record của giấy phép tương ứng.

3.9.3 Quy trình migration
Chuẩn bị: phòng Vật tư – TTBYT làm sạch master data trên Excel theo template. AssetCore không nhận file 'lộn xộn'.
Validate offline: chạy `python migrate_validate.py file.xlsx` để kiểm tra schema, bắt buộc, dropdown, date format. Có report lỗi.
Import dry-run trên staging: nhập sample 100 dòng đầu; review lỗi cross-field.
Import full trên staging: review tổng số dòng, tổng số lỗi, percentage success.
Stakeholder ký nghiệm thu sample 5% bản ghi đại diện.
Import production trong maintenance window; backup trước; rollback plan có sẵn.
Verify post-import: chạy DQ rules toàn bộ; report dashboard Data Quality; fix các vi phạm.
3.9.4 Nguyên tắc migration
Chỉ migrate dữ liệu master và asset registry; lịch sử PM/CM cũ chỉ migrate khi nghiệp vụ thực sự cần và có thể chứng minh quality.
Mỗi bản ghi import có cột tham chiếu legacy_id để truy nguồn.
Lifecycle Event 'imported_legacy' được sinh cho từng asset import, ghi rõ batch ID và file gốc.
Sau go-live, cấm import trực tiếp vào DB production; mọi data fix qua API hoặc UI có audit.
