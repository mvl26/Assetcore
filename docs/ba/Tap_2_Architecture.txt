Mục lục
2.1 Logical Architecture
AssetCore tổ chức theo 7 lớp kiến trúc logic. Quy tắc bất biến: business rule không được nhúng vào lớp UI; integration không được nhúng vào lớp domain; mỗi lớp chỉ phụ thuộc vào lớp ngay dưới nó. Mục tiêu là cô lập domain HTM khỏi hạ tầng để có thể thay framework, thay UI hoặc thay tích hợp mà không phá nghiệp vụ.
2.1.1 Sơ đồ 7 lớp
```mermaid
flowchart TB
  L1["L1 — User & Channel Layer\n(Web, Mobile PWA, Email, SMS, Telegram, Print)"]
  L2["L2 — Workflow & Application Service Layer\n(Form, List, Workflow, Notification, Print Format)"]
  L3["L3 — Domain / Business Layer\n(Engines: Lifecycle, Work Order, Document/QMS, CAPA, Metric)"]
  L4["L4 — Data / Document Layer\n(DocType, Master Data, Attachment, Index)"]
  L5["L5 — Integration Layer\n(REST/OpenAPI, FHIR, Webhook, ETL, Message Bus)"]
  L6["L6 — Analytics / Dashboard / Alert Layer\n(Snapshot, Drill-down, KPI, Alert Rules)"]
  L7["L7 — QMS / Governance Layer\n(Document Control, CAPA, Change Control, Audit, Mgmt Review)"]
  L1 --> L2 --> L3 --> L4
  L3 --> L5
  L5 --> L4
  L3 --> L6 --> L4
  L7 -.cross-cuts.-> L1
  L7 -.cross-cuts.-> L2
  L7 -.cross-cuts.-> L3
  L7 -.cross-cuts.-> L4
```

2.1.3 Nguyên tắc bất biến giữa các lớp
Domain layer (L3) không được import Frappe-specific HTTP/request module; chỉ dùng frappe.db, frappe.get_doc, frappe.new_doc.
Mỗi business rule có một module Python riêng trong L3, có unit test độc lập, không phụ thuộc UI.
Notification chạy qua một service queue duy nhất ở L2; không gửi email trực tiếp từ L3.
KPI ở L6 chỉ đọc snapshot; không tính lại on-the-fly từ transactional data trong dashboard production trừ khi data nhỏ.
L7 QMS audit log không bị ghi đè được; mỗi entry là append-only và có hash chain.

2.3.3 Quy tắc dependency
Sub-module không được import lẫn nhau theo chiều ngược lại của dependency graph.
`asset_registry` là sub-module gốc; mọi sub-module khác có thể đọc Medical Asset nhưng phải đi qua API của asset_registry để write.
`lifecycle` chỉ ghi nhận event, không sửa state nghiệp vụ — state sửa bởi sub-module sở hữu workflow tương ứng.
`audit` được gọi qua hooks tự động ở Frappe; sub-module khác không cần gọi trực tiếp.
`metric` đọc cross-module; cấm metric write back transactional state.

2.5.4 Observability
Mỗi background job log đầy đủ: job name, start, end, duration, doc affected, error nếu có.
Mỗi API endpoint log status code, latency, user, IP, payload size (không log payload thực tế trừ debug).
Mỗi state-change của workflow tạo audit entry và log structured JSON.
Prometheus metrics: latency p50/p95/p99 từng endpoint, queue depth, db connection, slow query.
Alert rules: queue depth > 1000 trong 10 phút; slow query > 5s; error rate > 1% trong 5 phút; db replication lag > 60s.
2.5.5 Maintainability & Deployability
Mỗi PR có CI chạy: lint, test, build, smoke deploy lên ephemeral env (≤ 8 phút).
Mọi schema migration phải reversible hoặc có rollback plan thủ công.
Code coverage tối thiểu 70% cho domain layer L3.
Tài liệu DocType, workflow, business rule cập nhật trong cùng PR sửa code, không lệch sprint.
2.6 Security & Compliance Architecture
2.6.1 Mô hình phân quyền
AssetCore dùng RBAC làm trục chính, bổ sung điều kiện ABAC để phân tách theo khoa và theo loại thiết bị. RBAC định ra có thể làm gì với DocType; ABAC định ra có thể làm với record nào.
2.6.2 Audit log architecture
Audit log của AssetCore có 3 lớp: Frappe Activity Log (tự động), AssetCore Asset Audit Log (custom append-only), QMS Audit Trail (cho document control).
```mermaid
flowchart TB
  ACT[Action by user] --> HOOK[Frappe Hook]
  HOOK --> FAL[Frappe Activity Log]
  HOOK --> AAL["AssetCore Asset Audit Log\n(append-only + hash chain)"]
  HOOK --> QAT["QMS Audit Trail\n(for Document Record / QMS Artifact)"]
  AAL --> EXP["Periodic export to immutable archive"]
  QAT --> EXP
```

2.6.5 Kiểm soát mật khẩu và phiên
Password tối thiểu 10 ký tự, có chữ hoa, số, ký tự đặc biệt; cấm 100 password phổ biến nhất.
Hash mật khẩu bằng PBKDF2-SHA256 hoặc Argon2id (theo Frappe default, không downgrade).
Session timeout 60 phút idle; absolute timeout 8 giờ.
Cookie HTTPOnly + Secure + SameSite=Lax.
CSRF token bắt buộc cho mọi state-changing request (Frappe default).
2FA bắt buộc cho role Manager, QMS, Sponsor, Admin; tuỳ chọn cho role khác.
Failed login: khoá tài khoản 15 phút sau 5 lần fail liên tục; alert đến IT.
2.6.6 Quản lý khoá và bí mật
Secret (DB password, API key, SMTP password) lưu trong file `site_config.json` ngoài git, mode 0600 owner = frappe.
Có vault tuỳ chọn (HashiCorp Vault hoặc Doppler) cho prod, key rotation 90 ngày.
API key cho integration external có scope tối thiểu, log truy cập, có thể rotate online.
Không commit secret vào git; CI có scanner.

2.7.3 Fixture strategy
`assetcore/fixtures/` chứa: Role, Workflow, Workflow State, Workflow Action, Custom Field, Property Setter, Notification, Print Format, Report, Dashboard Chart, Number Card.
Master data nghiệp vụ chuẩn (Risk Class catalog, Criticality catalog, Document Type catalog…) cũng đi qua fixtures với flag `is_standard=1`.
Fixture được seed bằng `bench --site <site> migrate` mỗi lần deploy; thay đổi fixture phải có patch tương ứng để cập nhật prod.
Demo data (sample asset, sample WO) tách thành fixtures riêng trong sub-package `assetcore/demo/`, chỉ load trên dev/staging.
2.7.4 Patch / migration strategy
Schema change qua DocType modify; AssetCore không sửa core ERPNext schema.
Data migration phức tạp đi qua patch trong `patches.txt` với tên dạng `assetcore.patches.v1_2.migrate_asset_risk_class`.
Patch phải idempotent: chạy nhiều lần không gây side-effect.
Patch phải có log structured: doc affected, count, error.

2.7.6 Quy tắc cấm trong code
Cấm `frappe.db.sql` raw có user input không tham số hoá.
Cấm `eval`, `exec` trừ trường hợp Server Script được kiểm soát qua workflow QA.
Cấm hardcode đường dẫn tuyệt đối.
Cấm log sensitive data (mật khẩu, token, attachment binary, payload PHI).
Cấm gọi external HTTP đồng bộ trong validate hook (phải dispatch qua RQ).
Cấm import lẫn nhau giữa sub-modules ngược chiều dependency graph (mục 2.3.2).
