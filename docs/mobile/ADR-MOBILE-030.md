## Context

Field-tech mobile màn **Chi tiết phiếu CM/sửa chữa** (`CMWorkOrderDetailView` / `RepairWorkOrderDetailView`) cần **đính ảnh bằng chứng cho TỪNG mục checklist nghiệm thu sửa chữa** (vd đo điện trở đất, test dòng rò, kiểm tra cơ khí) khi đóng phiếu — làm **bằng chứng NĐ98** cho thiết bị **Class C/D** (BR-09-15/16: ảnh bằng chứng per-mục checklist bắt buộc với thiết bị nguy cơ cao). Endpoint `imm09.attach_repair_checklist_photo` **ĐÃ LIVE** @`api/imm09.py:58` (single-step multipart: server đọc `frappe.request.files["file"]`, tự validate + tạo `File` private + set `repair_checklist[idx].photo` qua `frappe.db.set_value`, robust KHÔNG orphan như 2-bước `upload→file_url`) nhưng **CHƯA có trong OAS mirror** → codegen client mobile không sinh được method `attachRepairChecklistPhoto` → app phải hardcode URL + tự build multipart body.

Vòng này **curate 1 path POST** `attach_repair_checklist_photo` vào `assetcore-mobile.openapi.yaml` với requestBody **`multipart/form-data` DUY NHẤT** → codegen sinh method upload type-safe. **CONTRACT-ONLY**: handler+service+hằng đã LIVE @source (thêm ở phiên BE song song cùng branch, uncommitted), KHÔNG đụng `.py` vòng này ⇒ KHÔNG reload gunicorn, KHÔNG migrate.

Đây là **path multipart THỨ BA** của mirror, **bồi 1:1 theo template ADR-MOBILE-029** (`attachPmChecklistPhoto`, CR-14) — CÙNG shape media-type-multipart-only + `file:{format:binary}` + 200-oneOf + ladder 422 (gồm idx-row + corrupt) + 403 SINGLE `Forbidden` + **response 3-prop** `{file_url,file_name,checklist_item_idx}` + request 3-part + MAX=1/mục. **KHÁC-BIỆT CỐT-LÕI vs CR-14:** (1) **module IMM-09 / doctype `Asset Repair` / child `Repair Checklist`** (vs IMM-08 / PM Work Order / PM Checklist Result); (2) **discriminator `checklist_item_idx` = Frappe child `idx` (1-based)** — `Repair Checklist` **KHÔNG có** field STT domain riêng (khác PM Checklist Result CÓ `checklist_item_idx`) ⇒ `_find_repair_checklist_row` khớp `int(row.idx) == idx` (ADR-IMM09-PHOTO-01); (3) **permission = assignee (`assigned_to`) OR `repair.write`** (vs `pm.write`); (4) tag `work-order` (đối xứng — cùng convention imm09 POST write-action). **Cùng-hệt CR-14:** response 3-prop, request 3-part, MAX=1/mục, content-type 3-giá-trị, cap 10 MB, corrupt-guard, lifecycle hard-req.
