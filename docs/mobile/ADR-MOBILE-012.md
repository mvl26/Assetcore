## Context

Màn **`PMWorkOrderDetailView`** (mobile MVP-flow-4, tab PM của `MyWorkOrdersView`) có action-set **THIN**: KTV/Workshop Head mở `getPmWorkOrder` detail (`getPmWorkOrder`, ĐÃ wired — emit `allowed_transitions[]` từ R21) rồi cần **giao việc** cho 1 KTV hiện trường TRƯỚC khi KTV `submitPmResult` (§8.14, ✅ wired). Chuỗi PM-detail đúng = **`createPmWorkOrder`** (✅) → **`assignPmTechnician`** (**CÒN THIẾU** — mắt-xích-GIỮA) → **`submitPmResult`** (✅). Thiếu mắt-xích-GIỮA ⇒ PM WO `Open`/`Overdue` **không có endpoint dispatch** trên mobile-contract → màn detail render nút "Phân công" nhưng **không gọi được** (dead-end), buộc thao tác này phải làm trên web-FE. Đây là **parity** với repair: `createRepairWorkOrder → [assignTechnician] → startRepair` (§6458/ADR-IMM09-ASSIGN đã đóng). Vòng này bồi **1 path** (path/opId **43→44**), `info.version` GIỮ `0.1.0-skeleton`, 0 dangling `$ref`.

Service THẬT `assign_technician(name, *, technician, scheduled_date=None)` (`services/imm08.py:656`): guard 404 nếu WO∄ (`MSG.IMM08_WO_NOT_FOUND` `services/imm08.py:659`) + 409 nếu `wo.status ∉ {Open, Overdue}` (`MSG.IMM08_BAD_STATE` `services/imm08.py:661`) + 422 `VALIDATION` nếu asset (`services/imm08.py:663-666`) hoặc `pm_schedule` (`services/imm08.py:667-671`) đã bị xóa; set `assigned_to=technician`, `assigned_by=session.user`, `scheduled_date` (chỉ khi truthy `:674-675`), `status=PMStatus.IN_PROGRESS` (`:676`); `_transition_asset(wo.asset_ref, AssetStatus.UNDER_MAINTENANCE, wo.name)` (`:678` — asset → "Under Maintenance" + **sinh Lifecycle Event audit**); return **3-key** `{name, status, assigned_to}` (`services/imm08.py:679`).

`assignPmTechnician` khác `assignTechnician` (repair, §8.x/§6458) ở **3 điểm hợp đồng** cần quyết định:

1. **VERB-FLIP-THIS-ROUND (sibling imm08 của `add_measurement`).** Handler `assign_technician` (`api/imm08.py:46`) hiện **bare `@frappe.whitelist()`** ⇒ runtime BE **nhận cả GET** — nhưng đây là write-action DISPATCH (`status` Open/Overdue → In Progress + mutate `assigned_to` + asset-transition, **KHÔNG idempotent** ⇒ KHÔNG hợp GET-semantics). Đây là **verb-parity gap R33 BỎ SÓT**: R33 (VERB-PARITY CLOSURE) đã flip `submit_pm_result` (`imm08.py:54`) + 3 write-action imm11 sang `methods=['POST']` + làm rỗng `_PARITY_VERB_ALLOWLIST`→`set()` — **NHƯNG SÓT `assign_technician`** (cùng module IMM-08, cùng bare-`@whitelist` write-action). ⚠️ **Core Doc IMM-08 đã khai POST từ lâu** (`05_API_Specification.md §0` catalog row #3 = "POST"; `04_Backend_Design.md §5` code-sketch `@frappe.whitelist(methods=["POST"])` `:495`) ⇒ **doc đi trước code**; flip code = đưa source khớp doc-intent có sẵn. ⇒ Vòng này **flip ĐÚNG 1 dòng decorator** (`api/imm08.py:46`) **NGAY** (mirror ADR-MOBILE-011 add_measurement) ⇒ contract POST khớp source POST-only ⇒ **KHÔNG verb-divergence** ⇒ **KHÔNG** vào `_PARITY_VERB_ALLOWLIST` (giữ `set()` rỗng).
2. **`AssignPmTechnicianResponse` 3-key `{name, status, assigned_to}` — `status` = PMStatus, sau assign = "In Progress" (KHÔNG "Assigned").** SHAPE 3-key **TRÙNG** repair `AssignTechnicianResponse` (`{name,status,assigned_to}`) **NHƯNG `status` enum/value KHÁC**: PM dùng **PMStatus** 7-state (`services/imm08.py:43-50`), value-sau-assign literal **"In Progress"** (`PMStatus.IN_PROGRESS` `:676,679`) — repair dùng **RepairStatus** 9-state, value-sau-assign "Assigned" (`RepairStatus.ASSIGNED`). ⇒ **C3-split RIÊNG** (precedent ADR-MOBILE-009 `confirmInspection` KHÔNG reuse `CloseWorkOrderResponse` dù shape trùng — `status` enum INVARIANT khác). KHÔNG reuse repair `AssignTechnician*` (nếu reuse → codegen sinh PM-assign với `status.enum` = RepairStatus 9-state SAI máy-trạng-thái + example "Assigned" SAI domain).
3. **Optional field = `scheduled_date` (KHÁC repair `priority`).** Repair `assignTechnician` có optional `priority` (string default `''`); PM `assignPmTechnician` có optional **`scheduled_date`** (`scheduled_date: str = None` `api/imm08.py:47`; service set `wo.scheduled_date` chỉ khi truthy `:674-675`). ⇒ requestBody `required` EXACT `[name, technician]` (2 positional KHÔNG default) + optional `scheduled_date` `type:string`.

## Decision

**(1) `assignPmTechnician` — POST path mới, schema RIÊNG `AssignPmTechnicianResponse` 3-key.** Thêm 1 path `POST /api/method/assetcore.api.imm08.assign_technician` opId **`assignPmTechnician`** (UNIQUE camelCase — KHÁC repair `assignTechnician`), tag `work-order`, summary `[MVP-4] PM dispatch Open/Overdue→In Progress`. `AssignPmTechnicianResponse` closed (`additionalProperties:false`) **EXACT 3 prop** `{name string, status string, assigned_to string}` `required[name, status, assigned_to]` (cả 3 luôn trả — `services/imm08.py:679`). `AssignPmTechnicianEnvelope` closed `required[success,data]`, `success enum[true]`, `data = $ref AssignPmTechnicianResponse`. 200 = oneOf `[AssignPmTechnicianEnvelope, Error]` ở response-content-schema-level — route-by-VALUE `body.success` (C6/C7, **0 discriminator**), cả 2 nhánh closed + `success` enum disjoint `[true]`/`[false]`. **KHÔNG reuse repair `AssignTechnicianResponse`/`*ActionResponse`** (C3-split — `status` enum domain riêng).

**(2) `status` = PMStatus 7-state, value-sau-assign "In Progress".** `status.enum` = **PMStatus-canonical** `[Open, In Progress, Completed, Overdue, Cancelled, "Halted–Major Failure", "Pending–Device Busy"]` (`services/imm08.py:43-50` — đủ 7 state để codegen sinh đúng máy-trạng-thái), `example: In Progress` (`PMStatus.IN_PROGRESS` sau assign `services/imm08.py:676,679`). **KHÔNG** reuse RepairStatus 9-state, **KHÔNG** literal "Assigned" (đó là repair-domain). Lưu ý en-dash (–) trong "Halted–Major Failure"/"Pending–Device Busy" — copy byte-khớp source.

**(3) `requestBody` — INLINE (path-level, KHÔNG component), content `application/json` only, required EXACT 2 + optional `scheduled_date`.** Mirror repair `AssignTechnicianRequest` convention (§6486-6496 — INLINE `requestBody` + content `application/json` ONLY, **KHÔNG oneOf json+form** vì action đơn-record). `AssignPmTechnicianRequest` closed (`additionalProperties:false`) `required` EXACT = `[name, technician]` (2 positional KHÔNG default @`api/imm08.py:47`) + optional `scheduled_date` (`type:string` — `scheduled_date: str = None` @`api/imm08.py:47`). Cả 3 prop = `type:string`. `requestBody.required:true`.

**(4) VERB-FLIP-THIS-ROUND — flip bare→`methods=['POST']` NGAY, `_PARITY_VERB_ALLOWLIST` GIỮ `set()` rỗng.** Flip decorator `api/imm08.py:46` `@frappe.whitelist()` → `@frappe.whitelist(methods=['POST'])` — **ĐÚNG 1 dòng** (`git diff api/imm08.py` = đúng 1 dòng decorator; signature `api/imm08.py:47` + body `:48-51` + `rbac.require('pm.write')` `:49` UNCHANGED). Sau flip, `assign_technician` POST-only at source ⇒ contract POST khớp ⇒ **KHÔNG** vào `_PARITY_VERB_ALLOWLIST` (mirror ADR-MOBILE-011 — flip-this-round KHÔNG cần allowlist). Verb-parity full-sweep yaml↔runtime **zero-exception** GIỮ sau khi thêm path POST mới + flip.

**(5) 403 SINGLE-SHAPE + slot `{200,401,403}`.** 403 = SINGLE-SHAPE `Forbidden` (`$ref components/responses/Forbidden`) = dispatcher-403 (guest/no-token trip TRƯỚC `handle()`); in-handler cap-403 (`rbac.require('pm.write')` `api/imm08.py:49`) đã PHỦ bởi nhánh `Error` của 200-oneOf → slot 403 KHÔNG schema mới (mirror `submitPmResult`/`assignTechnician`/`startRepair`). 401 = `Unauthorized401` SINGLE-SHAPE. `assignPmTechnician` **∈ `_MVP_BUSINESS_PATHS`** (cap-gated write) **VÀ ∈ `_MVP_ACTION_ENVELOPE`** (map `→ AssignPmTechnicianEnvelope`) ⇒ 401∧403 symmetry tự cân (test so SET, +1 cả 2 slot).

**(6) `IMM08_WO_NOT_FOUND` (404) + `IMM08_BAD_STATE` (409) + `VALIDATION` (422) Error-on-HTTP-200 (ARRIVE nhánh Error, KHÔNG status-line).** WO∄ → `nthrow(MSG.IMM08_WO_NOT_FOUND, name=name)` (`services/imm08.py:659`) ⇒ Error `code=NOT_FOUND http_status=404` (`messages.py:561`); `status ∉ {Open, Overdue}` → `nthrow(MSG.IMM08_BAD_STATE, state=...)` (`services/imm08.py:661`) ⇒ Error `code=CONFLICT http_status=409` (`messages.py:582`); asset/`pm_schedule` đã xóa → `raise ServiceError(ErrorCode.VALIDATION, ...)` (`services/imm08.py:663-671`) ⇒ Error `code=VALIDATION_ERROR http_status=422`. CẢ BA đến trên **HTTP-200** (quirk §5, KHÔNG status-line). Client route theo `body.http_status` ∈ bounded enum `{400,401,403,404,409,413,422,429,500}` (R11) — **enum ĐÃ ⊇ {404,409,422}, KHÔNG đổi enum**. KHÔNG mở schema/slot status-line mới.

## Alternatives (rejected)

- **(a) reuse repair `AssignTechnicianResponse` / `*ActionResponse`** — shape 3-key trùng NHƯNG `status` enum khác domain: PM = PMStatus 7-state + value "In Progress"; repair = RepairStatus 9-state + value "Assigned". Reuse → codegen sinh PM-assign với enum/example SAI (state-machine repair áp lên PM). **C3-split RIÊNG** (precedent `confirmInspection` ADR-MOBILE-009). Loại.
- **(b) `status` literal-single `enum:[In Progress]`** (như `confirmInspection` `status.enum=[Completed]`) — assign chỉ chuyển sang "In Progress" nên có thể bound 1-value; NHƯNG return `wo.status` là field PMStatus đầy đủ (nếu BR sau này cho phép assign từ state khác → giá-trị khác) ⇒ khai đủ 7-state PMStatus an-toàn-forward (mirror repair `AssignTechnicianResponse` 9-state). Giữ enum 7-state, example "In Progress". (Quyết định B-mềm — chấp nhận full-enum.)
- **(c) optional `priority` (copy nguyên repair)** — PM `assign_technician` KHÔNG có `priority`; optional thật = `scheduled_date` (`api/imm08.py:47`). Copy `priority` = bịa field không có ở source. Loại — dùng `scheduled_date`.
- **(d) đẩy verb-flip → backlog + vào `_PARITY_VERB_ALLOWLIST`** (như §8.15 từng làm) — R33 đã đóng allowlist về `set()`; tái-mở = đi ngược closure. Flip 1-dòng rẻ hơn. Loại — flip-this-round (mirror ADR-MOBILE-011).
- **(e) requestBody `oneOf json+form`** (như `addMeasurement`/`createPmWorkOrder`) — repair `assignTechnician` (sibling action gần nhất) dùng INLINE json-only; PM assign mirror ĐÚNG sibling đó (action đơn-record, KHÔNG create-triad). Loại — json-only INLINE.
- **(f) khai status-line 404/409/422 cho `assignPmTechnician`** — lỗi nghiệp vụ in-handler arrive HTTP-200 + Error (route `body.http_status`), KHÔNG status-line (quirk §5). Slot GIỮ `{200,401,403}`. Loại.
- **(g) đưa `scheduled_date` vào `required`** — signature có default `=None` (`api/imm08.py:47`); service set chỉ khi truthy (`:674-675`). `required` 2-field. Loại.

## Consequences

- Mobile đóng **mắt-xích-GIỮA** PM-detail: `createPmWorkOrder → assignPmTechnician → submitPmResult` (parity repair `create → assign → start`). Workshop Head mở `getPmWorkOrder` (`Open`/`Overdue`) → có nút "Phân công KTV" gọi được; sau assign WO → "In Progress" + asset → "Under Maintenance".
- Path/opId **43→44** (`assignPmTechnician` 44). `info.version` GIỮ `0.1.0-skeleton`. 0 dangling `$ref`. Tất cả 44/44 operationId camelCase frozen.
- Codegen sinh: `assignPmTechnician(name, technician, scheduled_date?)` → `AssignPmTechnicianResponse` (đọc `status`/`assigned_to` để cập nhật UI detail). `status.enum` = PMStatus 7-state (KHÔNG repair 9-state).
- **⚠️ KHÔNG PURE-YAML (Hyrum) — đụng 1 dòng `api/imm08.py:46`.** Flip GET→POST shifts runtime `x-assetcore-stats`: **get 234→233 / post 254→255** (total GIỮ). ⇒ **re-baseline @source** (KHÔNG tin tuyệt đối số acceptance): `test_oas_d12_error_surface.py` `_BASELINE_GET 234→233`; `test_oas_d17_action_enum.py` `get_count 234→233` / `post_count 254→255`; re-verify ALL 13 `test_oas_*` (d8 derive n_post động → self-check). `_PARITY_VERB_ALLOWLIST` GIỮ `set()` (assign_technician POST-only sau flip).
- Guard: `TestMobileAssignPmTechnicianContract` (a..j) trong `test_mobile_oas` (`_EXPECTED_TEST_COUNT` bump từ **408**); RED-before/GREEN-after chứng minh cho MỌI TC mới. `test_imm08` thêm BE-unit kiểm `assign_technician` sinh **Lifecycle Event** (asset → Under Maintenance `services/imm08.py:678`) — audit-trail invariant. `test_mobile_docset` (path 43→44 + reconcile `_GUARD_SUITE_SUM`/`_MOBILE_OAS_TOTAL`/`_GUARD_SUITE_EXPECTED`) + `test_mobile_security_gate` (no-regress) GREEN @source.
